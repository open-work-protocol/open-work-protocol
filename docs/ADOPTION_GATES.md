# Adoption and Standardization Gates

## Gate 0 — Seed proof (current package)

- public spec and code;
- no mandatory founder service;
- TCK;
- local real-Git journey;
- narrow non-overlap boundary;
- governance/IP/antitrust/security packet.

## Gate 1 — Independent implementation

Require two implementations not controlled by the same organization. At least one must not reuse the Python reference core internally.

## Gate 2 — External conformance

An unaffiliated implementer runs the TCK and publishes results. Failures become protocol issues, not private patches.

## Gate 3 — Real work

At least three real Git work items complete using OWP semantics, including one cross-provider handoff. Synthetic fixtures do not satisfy this gate.

## Gate 4 — Community governance

At least three active maintainers from more than one organization; documented security contact/process; public roadmap.

## Gate 5 — Standards proposal

Choose the smallest venue/surface that fits demonstrated usage:

- A2A experimental extension if OWP remains primarily an A2A work-contract profile;
- AAIF project proposal if OWP has broader independent tooling/community;
- remain independent if external governance adds no value.

## Gate 6 — 1.0

Only after real compatibility history, security review, migration experience, and external implementations.

No gate may be marked complete by self-scoring alone.
