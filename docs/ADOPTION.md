# Community Adoption

The protocol only wins if mutually competing orchestrators all have a reason to implement it.

## Value to providers

- standardized stream of paid work;
- opaque internal architecture;
- no reverse-auction undercutting;
- portable proof of successful work;
- standard PASS behavior;
- resumable Git handoff;
- compatibility with adjacent open protocols;
- freedom to run their own board/router/validator.

## What the founding project should not do

Do not require a founder API key, canonical founder score, proprietary ledger, hidden tests, provider cost disclosure, or founder-controlled tollbooth.

## Birth sequence

1. Publish under Apache-2.0.
2. Mark 0.1 experimental.
3. Open a small number of hard RFC/issues.
4. Prove one real Git job.
5. Add a second independent provider.
6. Demonstrate cross-provider handoff.
7. Add x402/AP2/ERC-8004 bindings.
8. Seek A2A experimental-extension discussion only after wire semantics survive real use.
9. Move governance to multiple organizations quickly.

Standards legitimacy should be earned through interoperable code, not requested for an idea deck.
