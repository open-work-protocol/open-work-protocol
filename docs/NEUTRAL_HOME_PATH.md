# Neutral-Home Path

OWP should earn neutral governance before requesting it.

## Path A — A2A extension incubation

Because A2A already owns agent-to-agent task transport and explicitly permits independently developed extensions, the least-friction standards path is to prove the OWP work-contract semantics as an independent extension/profile first. If the A2A community finds the extension useful, OWP can seek the A2A experimental extension process without requiring a core A2A change.

OWP must not assume acceptance or reserve an A2A namespace before approval.

## Path B — AAIF project proposal

If OWP grows beyond one extension and has independent implementations/community health, AAIF is a plausible neutral home. Current AAIF public intake asks projects to demonstrate technical strength, broad usefulness, implementation quality/adoption, growth beyond one company or maintainer group, open governance/security practices, and a realistic 6–12 month roadmap.

OWP should not apply until it can show:

1. at least two unaffiliated provider implementations;
2. at least two independent validators/routers or one of each;
3. real work histories, not only synthetic demos;
4. a published TCK used outside the reference implementation;
5. documented security response and governance practice;
6. maintainers from more than one organization;
7. no mandatory founder-operated service.

## Path C — remain independent

Neutrality does not require foundation membership. If an independent repository plus multi-vendor governance serves implementers better, OWP can remain independent while keeping the same no-capture rules.
