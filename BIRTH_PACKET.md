# OWP Birth Packet

## One-sentence public thesis

**Open Work Protocol is an experimental open protocol for a customer or customer agent to post a Git-solvable outcome and a budget, have independent orchestrator teams ACCEPT/PASS based on private economics, route the work by verified quality, and return a finished result with portable evidence, payment linkage, bounded revision rights, and transferable handoff.**

## Why now

The adjacent pieces exist:

- **A2A**: opaque agent communication, task lifecycle, artifacts, extensions.
- **x402**: machine-native payment and portable signed offers/receipts.
- **AP2**: cryptographic agent purchase authority and mandate constraints.
- **ERC-8004**: portable agent identity, reputation signals, validation hooks.
- **Git/GitHub**: machine-verifiable software state, CI, PRs, short-lived scoped app access.

OWP standardizes the missing object: **paid outcome work**.

## The founding ask

Do not ask people to join a founder-owned marketplace.

Ask them to implement and break the protocol.

1. Implement one object in a second language.
2. Produce a DeliveryManifest from a different orchestrator.
3. Publish a quality scorer that disagrees with the reference scorer.
4. Run one real public Git issue end-to-end.
5. Transfer a rejected/steered attempt to another provider.
6. Add real payment/authority/trust profiles only after the core lifecycle works.

## Credibility test

If the founding team vanished tomorrow, could another team read the spec, run a board, implement a provider, route work, validate Git output, settle through its preferred rail, and preserve history?

If yes, OWP is infrastructure.
If no, it is a product API wearing an open-source costume.
