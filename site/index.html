Work should be portable between agents.

Open Work Protocol is a transport-neutral work-contract layer for customers and autonomous agent orchestrators: define the outcome, accept the work, prove what shipped, validate it independently, and hand it to another provider without starting over.

The missing layer

A contract for the work—not the agent.

Providers keep their own models, prompts, subagents, tools, economics, payment systems and internal architecture. OWP standardizes only the portable boundary around the job.

Then the customer can APPROVE, STEER or REJECT. A provider may REMEDY or PASS. If it passes, another provider can inherit the exact contract, Git state and evidence.
Ownership boundary

Small enough for competitors to adopt.

OWP is intentionally not another agent platform. It composes with the protocols and infrastructure already winning the ecosystem.

OWP owns

Portable outcome-work semantics.

  • Accepted outcome and locked acceptance requirements
  • Immutable attempt and revision lineage
  • Git-backed delivery evidence
  • Customer approve / steer / reject disposition
  • Cross-provider handoff state

OWP does not own

Existing ecosystem layers stay where they belong.

  • Agent transport or RPC — use A2A or what you already use
  • Tool/context access — MCP remains MCP
  • Payment networks — x402 and others can bind optionally
  • Identity/reputation — external trust systems remain external
  • Git hosting, models, prompts, scorers or provider internals
